## 1. Overview

### Objective

Reverse prompt engineering asks: given a piece of text produced by an LLM, what prompt most plausibly caused it? This is a generative inversion problem. The pipeline goes:

```
prompts.csv
    → [generate.py] → gold_dataset.csv          (LLM outputs)
    → [reconstruct.py] → reconstructions_t*.csv  (reconstructed prompts)
    → [evaluate.py] → results/                   (NOT YET IMPLEMENTED)
```

The task is well-defined: we have the true original prompt for every row in the dataset, so reconstruction quality can be assessed against a gold reference. The model is asked to behave like an analyst reading a finished advice response and inferring the human moment that motivated it.

### What "Reconstruction" Means Here

Given: an advice text `T` generated by LLaMA-3.3-70B-Versatile  
Target: a prompt `P*` (the true original human prompt)  
Output: a reconstructed prompt `P̂` such that `P̂ ≈ P*`

The approximation is many-to-one — multiple prompts can produce similar advice — so evaluation must measure semantic equivalence and structural completeness, not verbatim match. See §7.

### Domain

All 50 source prompts are **personal advice requests** across five topics:

| Topic | Count |
|---|---|
| Relationship | 10 |
| Workplace Sabotage | 10 |
| Friendship & Social Circles | 10 |
| Digital & Social Media | 10 |
| Family Dynamics | 10 |

Each prompt is tagged with a **Big Five personality style** (`Openness` or `Conscientiousness`) and a **level** (`High` or `Low`). This controls the tone and reasoning pattern of the generated advice — not the content of the prompt itself. The reconstruction task is therefore to recover the *content* of the original prompt from a response whose *style* was externally imposed.

| Style | High | Low |
|---|---|---|
| Openness | 15 | 10 |
| Conscientiousness | 15 | 10 |

## 2. Background & Failures

### 2.1 The Human vs. AI Classification Experiment — What Was Tried

The initial plan extended the reconstruction task into a classification setting: produce both AI-generated advice (via LLaMA) and human-written advice (sourced manually), run reconstruction on both, and train or evaluate a classifier to distinguish AI-reconstructed prompts from human-reconstructed prompts.

**What was built:**
- `gold_dataset_with_human.csv`: 50 AI-authored rows + 15 human-authored rows (65 total), with an `Author` column (`AI` / `Human`).
- Human outputs were collected for 15 prompts across all 5 topics (3 per topic).
- `reconstructions_t0_human.csv`: reconstruction run on the full 65-row mixed dataset at `temperature=0.0`.

**What failed:**

The AI detection classifier (used to validate the human samples) returned `AI-generated` for every single human-written output, even after:
- Introducing intentional spelling mistakes
- Adding informal phrasing and colloquialisms
- Writing shorter, more fragmented sentences

**Root cause (hypothesis):** Human-written advice on personal topics, especially when composed with some care, exhibits surface-level coherence, topic-sentence structure, and emotional vocabulary that overlaps heavily with the register LLMs produce when prompted to give empathetic advice. The classifier is not operating on deep syntactic or semantic features — it is picking up on genre-level signals, and advice-giving is a genre that humans and LLMs converge on stylistically.

**Why it was dropped and not salvaged:**
- Adding more noise degrades the human samples into incoherent text, which is no longer a fair test.
- Scraping Reddit/forum data would require ethics review and is out of scope.
- The classification framing is not required by Option 1. It was an overextension.

**What to remember:** The human rows in the dataset have `style=NaN` and `level=NaN`. They were not generated with the `Answer_prompt` template. Their outputs are longer (mean 158 words vs. 135 for AI), more anecdotal, and structurally irregular. Any metric that uses style/level matching will crash or produce nonsense on these rows.

## 3. Key Decisions & Rationale

### 3.1 Dropping Human/AI Classification

**Decision:** Removed.  
**Reason:** As described in §2. The classifier provided no signal. Continuing would have required a fundamentally different data collection strategy outside the project's scope.  
**Trade-off accepted:** The project loses the contrastive dimension. Reconstruction-only is narrower but evaluable.

### 3.2 Using Two Temperatures: 0 and 0.7

**Decision:** Run reconstruction at `temperature=0.0` and `temperature=0.7` on the same 50-item gold set, producing two parallel output files.  
**Reason:** Temperature directly controls output variability. At `t=0`, the model is deterministic — repeated runs on the same input produce identical output. At `t=0.7`, stochasticity is introduced, producing varied reconstructions that may surface different aspects of the source text.  
**What this enables:** A within-dataset comparison of reconstruction fidelity vs. diversity. The two files share the same `id` column, so they can be joined and compared row-by-row.  
**Observed divergence:** Mean Jaccard overlap between `t=0` and `t=0.7` reconstructions across all 50 pairs is **0.503**, indicating meaningful lexical divergence. The most divergent cases (overlap < 0.30) tend to involve `Conscientiousness/Low` and `Openness/High` conditions — see §8.

### 3.3 Model Choice: LLaMA-3.3-70B-Versatile via Groq

**Decision:** Use `llama-3.3-70b-versatile` through the Groq API with an OpenAI-compatible endpoint.  
**Reason:** Groq provides extremely low-latency inference, which matters when generating 50+ completions with `time.sleep(2.5)` rate-limit padding. The 70B model produces advice outputs with strong enough fidelity to the style/level constraint to make reconstruction non-trivial.  
**Trade-off:** Groq imposes rate limits — a 2.5-second sleep is hardcoded in `reconstruct.py` (0.6s in `generate.py`). Reducing these risks 429 errors. The API key in `.env` has been rotated across three accounts; use the currently active one (`LLM_API_KEY`).  
**Note on reproducibility:** At `temperature=0`, the Groq-hosted LLaMA endpoint behaves deterministically for our purposes, but Groq does not formally guarantee this across infrastructure changes. Re-running `t=0` after an infrastructure update may produce minor differences.

### 3.4 Prompt Design

**Two prompts are defined in `data/prompt.py`:**

`Answer_prompt` — used in generation. Instructs the model to produce advice in a specific personality style at a given level. The prompt is explicit about what High/Low means for each style, provides counter-examples, and adds hard constraints (no bullet points, 4–6 sentences, no psychological terminology).

`Reverse_prompt` — used in reconstruction. Instructs the model to infer the human moment behind the advice text. Key directives: write in first person, 2–3 sentences, end with a question or request. The prompt asks the model to do deliberate analytical reading before writing, not to reconstruct the system prompt, and to avoid meta-language about AI or personality.

**Why these designs:** The `Answer_prompt` needed to be prescriptive enough to produce stylistically distinct outputs that are non-trivially different across style/level conditions. The `Reverse_prompt` needed to constrain output length (early runs without length constraints produced 5–7 sentence reconstructions that were verbose and unfocused).

### 4.5 Key Structural Observation

This is a systematic bias: the `Reverse_prompt` instructs "2–3 sentences", but the model produces 3–5. The original prompts are crisp single-question requests. The reconstructions over-elaborate context and emotional framing. This length gap is itself an evaluable signal — it suggests the model is adding inferred backstory not present in the source.

## 5. Methodology

### 5.1 Full Pipeline

```
Step 1 — Prompt sourcing
  data/prompts.csv (50 hand-crafted prompts, Style/Level tagged)

Step 2 — Output generation [src/generate.py]
  For each prompt:
    Build Answer_prompt(Style, Level, Prompt)
    Call llama-3.3-70b-versatile (t=0.7, max_tokens=300)
    Write to data/gold_dataset.csv

Step 3 — Reconstruction [src/reconstruct.py]
  For each output in gold_dataset.csv:
    Build Reverse_prompt(output)
    Call llama-3.3-70b-versatile (t=0.0 or t=0.7, max_tokens=300)
    Write to data/reconstructions_t0.csv or data/reconstructions_t0.7.csv

Step 4 — Evaluation [src/evaluate.py]
  *** NOT YET IMPLEMENTED ***
  See §6 and §7 for full specification.
```

### 5.2 Prompt Templates (Abbreviated)

**`Answer_prompt`** — fills `{Style}`, `{Level}`, `{Prompt}`. Specifies Big Five definitions, High/Low behaviour for each, hard output rules (prose only, 4–6 sentences, no psych terminology, no preamble).

**`Reverse_prompt`** — fills `{output}`. Instructs multi-pass reading (content → emotion → persona inference), first-person voice, 2–3 sentences, ends with question, no meta-commentary, no AI references.

### 5.3 Rate Limiting

- `generate.py`: `time.sleep(0.6)` between calls — 50 items ≈ 30 seconds total
- `reconstruct.py`: `time.sleep(2.5)` between calls — 50 items ≈ 2 minutes total
- Do not reduce the 2.5s sleep in `reconstruct.py`. Groq's free tier rate-limits at the minute level.

## 7. Evaluation Methods — Implementation Detail

### 7.1 ROUGE (Lexical Overlap)

```python
from rouge_score import rouge_scorer

scorer = rouge_scorer.RougeScorer(["rouge1", "rougeL"], use_stemmer=True)
scores = scorer.score(reference=row["prompt"], prediction=row["reconstructed_prompt"])
r1_f1 = scores["rouge1"].fmeasure
rL_f1 = scores["rougeL"].fmeasure
```

**Interpretation:** ROUGE captures surface lexical overlap. Expect low scores (~0.15–0.30) because the reconstructed prompts paraphrase rather than reproduce. A drop to near-zero indicates the reconstruction is topically off. Use as a floor signal, not a ceiling.

### 7.2 Keyword / Constraint Recall

Extract the top 5–8 content keywords from the original prompt (nouns, proper names, situation-specific verbs). Check how many appear in the reconstruction, allowing for morphological variants.

```python
import re
from collections import Counter

def extract_keywords(text, stopwords):
    tokens = re.findall(r"\b[a-z]{4,}\b", text.lower())
    return [t for t in tokens if t not in stopwords]

def keyword_recall(original_kws, recon_text):
    recon_tokens = set(re.findall(r"\b[a-z]{4,}\b", recon_text.lower()))
    hits = sum(1 for kw in original_kws if kw in recon_tokens)
    return hits / len(original_kws) if original_kws else 0.0
```

**Why this matters:** The reconstruction task is fundamentally about recovering the *situation* described in the prompt. A reconstruction that gets the emotional register right but misses the specific situation (e.g., "debt collector" → vague financial problem) should be penalised. Keyword recall catches this.

### 7.3 BERTScore (Semantic Similarity)

```python
from bert_score import score as bert_score

refs  = list(df["prompt"])
hyps  = list(df["reconstructed_prompt"])
P, R, F1 = bert_score(hyps, refs, lang="en", verbose=False)
df["bert_f1"] = F1.numpy()
```

**Interpretation:** BERTScore captures semantic similarity using contextual embeddings. It is the primary metric for this task because paraphrastic reconstructions that are semantically equivalent to the original prompt should score highly even with low ROUGE. Target mean F1 > 0.85 as a rough adequacy threshold.

### 7.4 Human Evaluation Rubric

Apply to a stratified sample of 20 rows (5 per style/level cell, selected randomly). Evaluate both `t=0` and `t=0.7` reconstructions for the same row independently.

Score each reconstruction on four dimensions (0–4 each, max 16):

| Dimension | 0 | 2 | 4 |
|---|---|---|---|
| **Intent accuracy** | Wrong task/goal entirely | Partially correct — right domain, wrong ask | Correct task and goal recovered |
| **Constraint coverage** | Misses core situation details | Recovers some specifics | All key constraints present |
| **Stylistic plausibility** | Sounds like a bot or prompt engineer | Mostly plausible but slightly formal | Reads like a real person in distress |
| **Completeness** | Truncated or missing the question | Has a question but it is generic | Specific, contextually grounded question |

**Instructions for annotators:**
- Read the `output` (advice text) first. Then read the `prompt` (ground truth). Then score the reconstruction without looking back at `prompt`.
- Score independently — do not adjust for the other temperature variant.
- If you are unsure between two scores, pick the lower one.

### 7.5 Error Analysis

Categorise every reconstruction that scores below 10/16 on the human rubric into one of these error types:

| Error Type | Description | Example |
|---|---|---|
| `missing_constraint` | Key situational detail from the original prompt is absent | Original mentions "debt collector"; reconstruction says "financial stress" |
| `style_mismatch` | The reconstruction matches the advice's imposed style, not the prompt's neutral voice | Reconstruction sounds curious/exploratory because the advice was High Openness |
| `hallucination` | Reconstruction introduces facts not inferable from the advice text | Adds a third party, a location, or a relationship dynamic not in the output |
| `over_generic` | Reconstruction is topically correct but so vague it could fit dozens of prompts | "I need help with a relationship problem, what should I do?" |
| `length_overrun` | Reconstruction is more than 3x the length of the original prompt | More than ~140 words |

Log error types in the results CSV. Compute frequency per error type and per style/level cell.

## 8. Observations

### 8.1 Temperature Effects

The mean Jaccard word-overlap between `t=0` and `t=0.7` reconstructions is **0.503** — roughly half of the vocabulary is shared across the two runs. This is meaningful divergence. However, the *length* is nearly identical (76.9 vs. 76.3 words average), suggesting temperature affects lexical choice and framing rather than structural verbosity.

The most divergent cases (overlap < 0.30) cluster in:
- `Conscientiousness/Low` (casual, spontaneous advice → reconstruction can go in multiple directions)
- `Openness/High` (exploratory, multi-interpretive advice → reconstruction is underdetermined)

The most convergent cases are likely `Conscientiousness/High`, where advice is structured and step-oriented — leaving less ambiguity about the underlying situation.

### 8.2 Systematic Over-length

Every reconstructed prompt is longer than the original. The `Reverse_prompt` instructs "2–3 sentences" but the model consistently produces 3–5. Original prompts average 46.5 words; reconstructions average ~77 words. The model adds emotional framing and contextual backstory not present in the source prompt. This is evaluable as a `length_overrun` error and should be quantified.

### 8.3 Style Bleed

A qualitative observation (not yet quantified): reconstructions for `High Openness` outputs sometimes adopt an exploratory, uncertain voice in the reconstruction itself — e.g., hedged questions, "I'm not sure what to make of this." Original prompts in this condition are direct question-askers, not hedgers. The reconstruction appears to absorb the stylistic register of the advice it is reading, rather than inferring the plainer register of the person who wrote the prompt. This is a form of `style_mismatch` and warrants targeted error analysis.

### 8.4 Topic-Level Patterns

No quantitative topic breakdown has been run yet. Hypothetically, `Digital & Social Media` prompts (involving finsta accounts, cryptic posts, online behaviour) may be harder to reconstruct because the advice is more abstract and situation-specific details are less recoverable. `Relationship` prompts are the most concrete and may yield the best reconstruction scores.

## 9. Limitations

### 9.1 Classifier Bias Toward AI Interpretation

The `Reverse_prompt` was written and tested by a researcher using LLM-generated advice. It may have been implicitly optimised to reconstruct LLM-style advice well. Its performance on genuinely human-authored advice (informal, anecdotal, structurally irregular) is unknown and may be poor. This is not a current problem — the dataset is 100% AI-generated — but it limits generalisability.

### 9.2 Temperature Sensitivity

The reconstruction task was run at two temperatures as a comparison, but there is no principled argument for why `0.7` is the right stochastic setting. A temperature sweep (0, 0.3, 0.5, 0.7, 1.0) would give a cleaner picture of the accuracy-diversity curve. Only two points are sampled.

### 9.3 Single-Model Pipeline

Both generation (`generate.py`) and reconstruction (`reconstruct.py`) use the same model (`llama-3.3-70b-versatile`). This introduces self-referential bias: the reconstructor has seen outputs produced by the same model family and may have learned implicit patterns in how that model structures advice. Cross-model evaluation (generate with LLaMA, reconstruct with GPT-4o or Gemini) would isolate this.

### 9.4 Evaluation Not Yet Run

`src/evaluate.py` is empty. All observations in §8 are preliminary and qualitative. None of the claims above have been confirmed by automated metrics. Treat §8 as hypotheses to test, not findings.

### 9.5 Dataset Size

50 items is small for robust subgroup analysis. With 4 style/level cells (15 High, 10 Low per style), cell sizes are 10–15. Metric estimates in these subgroups will have high variance.

### 9.6 Prompt Not in the Output

The `Answer_prompt` template explicitly strips all meta-information from the generated advice — no mention of personality style, Big Five, or the original prompt. This is intentional design, but it means the reconstructor has zero explicit signal about style/level. Whether `High Openness` advice is meaningfully distinguishable from `Low Conscientiousness` advice in practice has not been tested. If the styles are not recoverable from the surface text, the style/level variable adds no information to the reconstruction task.

## 6.2 Why Human Annotation Was Dropped

The original README specified human annotation on 20 rows using a 0-16 rubric across four dimensions. This was not conducted for the following methodological reason:

Automated metrics reveal that the reconstruction pipeline operates primarily as advice compression rather than genuine prompt inversion — BERTScore between reconstruction and original prompt (0.890) and between reconstruction and advice output (0.867) differ by only 0.023. Given this finding, human fluency evaluation would not address the core limitation identified. A reconstruction can read as natural and plausible while still failing to recover the original prompt's specific situational content. Rubric-based fluency scoring would therefore flatter the system without measuring what matters. The automated metrics — particularly the BERTScore diagnostic and keyword recall — provide a more honest and more rigorous characterisation of system performance than subjective fluency scoring would.

This decision is documented here for transparency and should be explicitly addressed in the write-up's methodology section.

## 6.4 Interpretation of Results — Key Findings for the Report

### Finding 1 — Compression not inversion (central finding)
The BERTScore gap between reconstruction vs prompt (0.890) and reconstruction vs advice output (0.867) is only 0.023. This is within noise range for BERTScore and means the reconstruction is almost equally similar to the input it was given as to the target it was supposed to recover. The model is paraphrasing the advice text, not reversing the generation process. This finding undermines the headline metric of 0.890 as evidence of successful prompt recovery — a system that simply summarises the advice output would score similarly.

### Finding 2 — BERTScore flatters, keyword recall is honest
Keyword recall at 0.265 against BERTScore at 0.890 is the most important internal comparison. The model captures emotional register and general topic (high semantic similarity) but loses specific situational facts (low keyword recall). This reflects a fundamental property of advice discourse: advice responses abstract concrete situational details into emotional generalities, and the reconstruction follows the abstracted register rather than recovering the original specifics. This is a genuine linguistic finding about genre transformation.

### Finding 3 — Temperature is irrelevant
BERTScore difference between t=0 and t=0.7 is 0.001 despite Jaccard overlap of only 0.503. Half the vocabulary changes but quality does not move. Temperature affects surface lexical choice, not semantic recovery. The ceiling is set by information available in the advice text, not by decoding strategy.

### Finding 4 — Personality conditioning had no detectable effect
All style and level conditions fall within 0.003 BERTScore. Either the Big Five conditioning did not produce sufficiently distinct outputs for the reconstructor to detect, or the reconstruction ignores stylistic signal regardless of how the advice was written. The data cannot distinguish between these explanations. Both are worth naming in the write-up.

### Finding 5 — Systematic over-elaboration
Length ratio 1.663 consistently across every condition. Reconstructions average 77 words against original prompts averaging 46. The Reverse_prompt instructs 2-3 sentences but the model produces 3-5. The model infers and adds emotional backstory not present in the source prompt — consistent with the compression hypothesis. This is a quantifiable and consistent bias.

### Finding 6 — Topic variation exists but should not be overclaimed
Friendship reconstructs best (keyword recall 0.343), Relationship worst (0.216). Workplace Sabotage has lowest BERTScore (0.885). With n=10 per topic these are directional observations only. Report them as patterns, not robust findings.
